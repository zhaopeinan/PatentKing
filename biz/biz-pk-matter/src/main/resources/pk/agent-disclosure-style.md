# PatentKing 专利代理交底规范（金标准对照）

对照范本（专利代理撰写原文）：`ground_truth_file/面向单候选文本到SQL转换的双重自适应生成方法.docx`

平台生成的一切交底 Markdown / Word **须与下列结构、格式、措辞保持一致**，成文后须调用 `pk_align_disclosure` 自动比对并修订至通过。

---

## 一、章节结构（顺序固定，标题字面一致）

| 序号 | 章节 | 说明 |
|------|------|------|
| 0 | 发明名称 | 单行，与权利要求主题一致 |
| 1 | 权利要求书 | 独立权利要求 + 从属权利要求 + 计算机程序产品项（软件类发明） |
| 2 | 技术领域 | 一段，固定句式见下 |
| 3 | 背景技术 | 客观陈述现有方案及不足，不用「本文」「我们」 |
| 4 | 发明内容 | 痛点 → 方案概述 → 第一方面步骤 →「在一些可选的实施方式中」展开 |
| 5 | 附图说明 | 逐条「图N为……」或「见说明书附图N」 |
| 6 | 具体实施方式 | 与附图、步骤一一对应，可实施细节 |

Markdown 中用二级标题映射，例如：`## 权利要求书`、`## 技术领域`（**禁止**改成「二、技术背景」等变体）。

---

## 二、金标准措辞模板（须逐项对齐）

### 技术领域

> 本发明涉及【技术大类】和【细分】技术领域，具体涉及一种【发明名称】。

示例：本发明涉及大语言模型和数据库技术领域，具体涉及一种面向单候选文本到SQL转换的双重自适应生成方法。

### 背景技术

- 先写现有技术路线（「现有系统通常采用……」），再用 **「但是，上述技术方案在……场景中，……」** 点明稳定缺陷。
- 禁止论文套话（「具有重要意义」「本文首次」）。

### 发明内容

- 开篇：**「针对现有技术存在的不足，本发明提出一种……，以解决现有技术中存在的、……的技术问题。」**
- 过渡：**「本发明采用的技术方案如下：」**
- 总方案：**「第一方面，提供了一种……，包括以下步骤：」** 后接与独立权利要求一致的步骤列表。
- 从属展开：每条用 **「在一些可选的实施方式中，……」**（与从属权利要求一一呼应，可多条）。

### 权利要求书

- 独立项：`1.一种【发明名称】，其特征在于，包括以下步骤：`（方法类）或 `其特征在于，包括：`（系统/装置类）。
- 步骤：每条独立成行；动词统一「获取 / 基于 / 根据 / 执行 / 输出」等。
- 从属项：`N.根据权利要求X所述的【发明名称】，其特征在于，……`；多项特征可分段，用 **「所述……；所述……。」**
- 术语：全文 **所述** 指代前项；参数用 **预设**（如「预设令牌阈值」）。
- 软件发明最后一项：`一种计算机程序产品……实现权利要求1-N任一项所述……之步骤。`

### 附图说明

- 摘要段后可写 **「见说明书附图1」**；正文附图说明逐图描述模块/步骤关系。

### 具体实施方式

- 与「发明内容」步骤编号、模块名、附图标号 **完全一致**。
- 参数、数据结构、异常与回退写清；禁止留「等」而不定义。

---

## 三、格式与排版

- 权利要求：**不用 Markdown 列表符号**，用 `1.` `2.` 编号段落；步骤不合并成长段（代理稿每步一段）。
- 说明书段落：完整句，分号只在摘要串联步骤时使用。
- **禁止**写入：联系人、委托确认、注意事项、平台操作说明、查新清单、自检清单。
- 附图：正文用 mermaid 结构预览；Word 导出前须机器渲染，图题格式「图1 ……」。

---

## 四、对齐流程（Agent 必遵）

1. 完成交底正文初稿。
2. 调用 **`pk_align_disclosure`**（传入完整 Markdown）。
3. `ok=false`：按返回的 `checklist` 修订后 **再次调用**，直至 `ok=true`。
4. 通过后且用户已确认 Word → 调用 **`pk_export_disclosure`**。

## 五、对照范本摘要结构（NL2SQL 案例）

- 独立权利要求 9 步 + 程序产品权利要求 + 9 项从属 + 应用场景从属。
- 说明书五段式 + 具体实施方式逐步展开 DDL 增强、检索、滑动窗口模式链接、安全网补全、列消歧、单候选 SQL、后处理、错误修订等。

其他技术主题须 **复用同一结构与时态措辞**，仅替换技术实体名称与步骤内容。
